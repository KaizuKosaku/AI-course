## 1. この回のねらい

これまでの4回は「AIに書かせる」授業でした。今日はそこに1つだけ新しいことを足します。**AIに任せて、その間に自分は別の仕事をする。**

Manusのようなエージェントは、指示を受けたあと自分で計画を立て、10〜30分ひとりで作業を続けます。その間、生徒は手が空きます。**この「空き時間」こそが今日の教材**です。待っているのではなく、別の仕事を並行して進める——AIを使う人間の働き方が、そのまま授業の形になります。

集大成としての位置づけは、後半で書く**企画書1枚**に集約されます。

| 企画書の項目 | 対応する回 |
|---|---|
| 誰のため？何のため？ | DAY02（探究・問いを立てる） |
| どんな画面で、何ができる？ | DAY03（言葉でアプリを作る） |
| 完成の基準（できていたら◯） | DAY04（設計書・受け入れ基準） |
| スライドに入れる主張と根拠 | DAY02（調べる・整理する・伝える） |
| AIはどこまでやれるのか | DAY01（AIを知る） |

冒頭でこう言い切ってください。**「今日書く1枚の紙の中に、これまでの4回が全部入っています」**

## 2. 到達目標と評価の観点

作品の出来では測りません（DAY04と同じ方針）。

| 到達目標 | 何を見るか |
|---|---|
| 人の依頼に応える企画書が書ける | 「誰のため」が具体的な1人になっているか（「みんな」は不可） |
| AIに任せ、途中で口を出せる | エージェントの計画を読んで、1回でも介入した跡があるか |

## 4. 各パートの進行

### 01 ｜ 導入（8分）

3つだけ伝えます。

1. **今日は、自分で作る仕事と、任せる仕事の両方がある。**
2. **後半、AIが働いている間、みんなは待たない。別の仕事をする。**
3. **ミッションカードは、空いた時間に上から進める。全部やる必要はない。**

ミッションカードの説明を**必ずここで済ませてください**。後半に入ってから説明すると、待ち時間が説明時間で潰れます。カードは配布済みの状態で授業を始めます。

> **新規生徒への声かけ**
> 「これまでの4回のことは、今日AIに教えてもらいます。先生は説明しません。」
> ここで安心させておくと、置いていかれた感じを持たずに前半に入れます。

### 02 ｜ 前半：自分のアプリ開発（38分）

**既存生徒 ── 前回の続き**

DAY04で書いた設計書とアプリを開いて、続きから進めます。まずWANT（あったらいい機能）を1つ足す、から入るとエンジンがかかります。

> ⚠ **事前リマインド必須**：前回のAI Studioのプロジェクトと設計書が残っているか、授業前に確認させてください。消えている生徒がいると前半が丸ごと止まります。予備として、DAY04の設計書テンプレートを印刷して用意しておいてください。

**新規生徒 ── 0から。ただし最初の10分は「教材要約ミッション」**

いきなり作らせず、AIに過去4回を教えてもらうところから始めます。これが**カード C1（必修）**です。

渡すもの：DAY03・DAY04の教材テキスト（優先）、余裕があればDAY01・DAY02も。

生徒が打つプロンプト（3段階・カードに印刷）：

```
① これは私が受けていない授業の教材です。
   中学生の私に向けて、この回で学んだ一番大事なことを3行で説明して。

② この教材に出てくる専門用語だけを表にして、
   それぞれ意味を1行で書いて。

③ この回でやった作業を私が今日やるとしたら、
   手順を箇条書き5つで書いて。
```

成果物は**「1回3行 × 4回＝12行のメモ」**。これが新規生徒の地図になります。10分経ったら、地図を手元に置いたままアプリ作りへ移ります。完璧に理解してから作り始める必要はない、と伝えてください。

**共通ルール**

- 詰まったら **カード C2（バグ報告文を書く）** へ。
- 早く形になったら **カード A1〜A5** へ。手が止まった状態で座らせないのが、この38分の設計です。

### 03 ｜ 企画書を書く（13分）

**お題（既定案）**

> **小学1年生が、◯◯を好きになるゲームを作ってください。**
> （◯◯＝計算／漢字／都道府県 など、生徒が選ぶ）

対象が明確で「誰のため」が書きやすく、新規生徒でもすぐ理解できます。差し替える場合は、この1行を変えるだけで以降の資料はそのまま使えます。

**企画書テンプレート（A4・1枚）**

```
【タイトル】

【誰のため】← 具体的に1人。名前をつけてもいい。
  例：「算数が嫌いで、宿題の前に必ず泣く小1のユウタくん」

【その子の困りごと／楽しませたいポイント】

【どんなゲーム】← 30字以内で言い切る

【画面と操作】← 3つだけ
  1.
  2.
  3.

【完成の基準】← ◯がつく条件を5つ。あとで検証に使う。
  1.
  2.
  3.
  4.
  5.

【やらないこと】← 1つ以上。必須。
  例：「音は出さない」「ステージは1つだけ」
```

> ⚙ **「やらないこと」を必ず書かせてください。**
> AIは書かれていないことを勝手に足します（DAY04の核心）。範囲を切るのは人間の仕事で、ここが企画書の中で一番「人間らしい」欄です。既存生徒には「前回の続きだよ」と言えば通じます。

**「誰のため」が「みんな」で止まっている生徒には**、机間巡視で一言だけ。「その"みんな"の中の、1人だけ思い浮かべて。名前は？」

### 04 ｜ 依頼文に変換して投下（7分）

企画書の下に、この3行を足すだけで依頼文になります。

```
上の企画書のとおりに、次の3つを作ってください。

1. ブラウザで遊べるゲーム（HTMLファイル1つにまとめる）
2. 企画スライド5枚
   （表紙／誰のため／どんなゲーム／画面と操作／完成の基準）
3. 完成したら、上の「完成の基準」5つを1つずつ確認して、
   満たせたか・満たせなかったかを報告してください。
```

> ⚙ **3番が今日の隠れた主役です。**
> エージェントに自己チェックを要求する、という発想を持ち帰らせてください。ただし「AIの自己申告は信じない」も同時に伝えます。06で人間が確かめ直します。

> ⚙ **「完璧な依頼文を書いてから投げる」をやらせないこと。**
> エージェントは途中で口を出せます。**早く投げて、途中で直す**ほうが速い。7分でタイマーを鳴らして、書けていなくても投げさせてください。これは今日の重要な学びの1つです。

### 05 ｜ 待ち時間：ミッションカード＋中間介入（23分）

生徒は基本的にカードを進めます。ただし**5分に1回、全体に声をかけて**Manusの画面を見に行かせてください。

**中間介入の見方（黒板に貼る3行）**

1. AIが立てた**計画**を読む。順番はおかしくないか？
2. 自分の企画書と**違うこと**をやっていないか？
3. 違ったら、その場で「そこは違う。◯◯にして」と入力する。

> ⚙ ここが今日いちばん価値のある3分です。
> **エージェントの作業ログを読む**という経験は、他ではまず得られません。「AIが何を考えて動いているかを、人間が読んで割り込む」——これができる人とできない人で、AI時代の差がつきます。1回も介入していない生徒には、必ず声をかけて1回入れさせてください。

**この時間にやらせたいカード：B群（疑う）**。特に **B1・B2** は、次の06にそのまま接続します。

### 06 ｜ 検証と修正指示（12分）

**手順（黒板に貼る）**

1. 企画書の「完成の基準」5つを見る。
2. **自分で1つずつ確かめる**。AIの自己申告は読まない。
3. 満たしていないものを**1つ**選ぶ。
4. 「基準の◯番が満たせていません。△△になっているので、□□にしてください」とだけ伝える。
5. 直ったか確認する。

> ⚙ **「なんかイマイチ」で修正指示を出させないこと。**
> 基準の番号を言わせる。これがDAY04から一貫している、この教室の作法です。既存生徒には「07の完成の基準、覚えてる？」で通じます。

**成果物が返ってこない／失敗した生徒には**、先生の完成見本を渡して、そちらを検証させます。**検証のスキルが今日の目標なので、自分の成果物でなくても目標は達成できます。** ここは必ず用意しておいてください。

## 5. ミッションカード

**1枚3〜5分、成果物は1〜3行のメモ。** 空いた時間に上から進めます。全部やる必要はありません。

各カードには「使いどころ」を書いてあります。**順番よりも、いま自分がやっている作業に効くカードを選ばせる**ほうが定着します。

### A群 ── 型を覚える（前半・手が空いたとき）

| # | ミッション | 持ち帰る型 |
|---|---|---|
| A1 | 好きな文章を「条件なし」と「小学生向けに・3行で・数字は必ず残して」の2回要約させ、見比べる | **誰に・どれだけ・何を残すかを指定する** |
| A2 | 何かを相談するとき「1案だけ出さないで。3案と、それぞれの弱点も書いて」と頼む | **AIに選ばせない。選ぶのは自分** |
| A3 | 同じ質問を「表で」「箇条書き5個で」「1行で」出させる | **出力の形は指定できる** |
| A4 | 同じ質問を「小学校の先生として答えて」「ゲーム会社の社長として答えて」で聞く | **役割を与えると答えが変わる** |
| A5 | お手本を1つ見せてから「これと同じ形式で3つ作って」と頼む | **例を1つ渡すと精度が上がる** |

### B群 ── 疑う（待ち時間）

| # | ミッション | 持ち帰る型 |
|---|---|---|
| B1 | AIが出した数字か固有名詞を1つ選び「出典は？」と聞く | **根拠を要求する** |
| B2 | 長めの回答をもらったあと「この中で自信がないのはどこ？」と聞く | **AIに自己申告させる（が、信じすぎない）** |
| B3 | わざと間違った前提で質問し、AIが訂正してくるか観察する | **AIは間違いに合わせてくることがある** |
| B4 | 同じ質問を2つの違うAIに投げ、答えの違いを1つ見つける | **1つのAIの答えを正解にしない** |

### C群 ── 使い倒す（実務）

| # | ミッション | 持ち帰る型 |
|---|---|---|
| **C1** | **【新規生徒必修】教材を渡して、過去回を3行で要約させる（→ 02参照）** | **長い資料は、読む前にAIに地図を描かせる** |
| C2 | 自分のアプリの不具合を「症状・再現手順・期待する動き」の3点で書いてAIに渡す | **バグは感想でなく事実で伝える** |
| C3 | 自分の企画に「弱点を10個挙げて」と頼み、1つだけ企画書に反映する | **反対意見を先に取りに行く** |
| C4 | 何かの作業を「完成の基準を10項目のチェックリストにして」と頼む | **基準は先に作る** |
| C5 | 手元の数字（好きなデータでよい）を渡して「表にして、気づいたことを3つ」と頼む | **データは眺めずAIに読ませる** |

> ⚙ **カードの回収方法**
> 「クリアしたカードの番号と、持ち帰った型を1行」だけメモさせます。提出物を重くすると誰もやりません。授業の最後に「今日いちばん効いたカードは？」と1問だけ聞けば十分です。

## 6. 教材要約ミッション（C1）の準備 ── 要対応

**そのままのHTMLを渡すと、要約の精度が落ちます。**

| ファイル | HTMLサイズ | 実際の本文 |
|---|---|---|
| ai01-生徒.html | 145KB | 17,545字 |
| ai02-生徒.html | 138KB | 17,539字 |
| ai03-生徒.html | 133KB | 14,269字 |
| ai04-生徒.html | 122KB | 14,093字 |

**中身の9割がCSSとSVG**です。ファイルアップロードなら通りますが、AIの注意がデザイン定義に食われて要約が薄くなり、チャット欄への貼り付けは長さ制限で失敗します。

対策は3つ、上から推奨順です。

1. **本文だけを抜き出したテキスト版（`ai0X-要約用.txt`）を配る** ── 各1万4千〜1万7千字。どのAIでも確実に通り、要約の質が安定します。
2. **生徒ページのURLを渡す** ── 公開されていて、かつ使うAIがWebを読める場合のみ。
3. **あえて生のHTMLを渡す** ── 上級者向け。「AIに渡す資料は、渡す前に人間が整える必要がある」という気づきを狙う場合はこちら。ただし新規生徒には負荷が高いので、既存生徒の追加ミッションに回してください。

## 8. 想定トラブルと対処

| 起きること | 対処 |
|---|---|
| Manusが時間内に返ってこない | 先生の完成見本を渡して検証させる。目標は検証スキルなので達成できる |
| クレジット切れ | 3人組で1アカウントを共有し、画面を全員で見る。むしろ介入の議論が生まれる |
| 既存生徒の前回データが消えている | 設計書テンプレートを渡して、その場で書き直させる（10分で足りる） |
| 新規生徒が要約で止まる | 3段階プロンプトの①だけでよい、と伝える。地図は粗くていい |
| 生徒が待ち時間に何もしない | カードの説明が01で不足している。次回は必ず冒頭で回し方まで説明する |
| 前半が盛り上がりすぎて終わらない | 38分でタイマー。「アプリは持ち帰って続けられる、企画書は今日しか書けない」と言って切る |
