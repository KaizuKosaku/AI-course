## フォルダーの形

```

src/ai.js                AIを呼ぶ関数（先生が用意。変更しない）

```

## 手元で動かす

| やること | コマンド |
|---|---|
| 最初の1回と、パッケージを足したとき | `npm install` |
| データベースの形を手元に反映する | `npx wrangler d1 migrations apply DB --local` |
| 動かす | `npx wrangler dev` → ブラウザで `http://localhost:8787` を開く |
| 止める | ターミナルで `Ctrl + C` |

手元のデータベースは練習用。公開中の作品のデータとは別のもの。

## URLと、処理の分かれ方

- 公開すると、作品は `https://（作者の名前）.kaizuacademy.com` で世界中から見られる
- `public/` にあるファイルは、そのURLでそのまま配られる（例：`public/index.html` → `/`、`public/game.js` → `/game.js`）
- `public/` にないURL（例：`/api/score`）へのアクセスだけが、`src/index.js` の `fetch()` に来る。サーバーの処理は `/api/` などで始まるURLにするとわかりやすい

## 使える技術

追加の費用なしで使える。作者の理想に必要なら、ためらわずに使ってよい。

| 部品 | できること | 使い方 |
|---|---|---|
| Cloudflare Workers | サーバーの処理 | `src/index.js` に書く |
| 静的アセット | 画面のファイルを配る | `public/` に置く |
| D1 | データベース | `env.DB`。すぐ使える |
| KV | 簡単な保存（設定、カウンターなど） | `env.KV`。すぐ使える |
| R2 | 画像や音などのファイル置き場 | `env.FILES`。すぐ使える |
| Durable Objects | リアルタイム通信、複数人の同時接続（WebSocket）、ずっと続く部屋や世界 | `env.ROOM`。クラスは `src/room.js` の `Room`。すぐ使える |
| Cron トリガー | 決まった時刻に自動で動く処理 | 毎日、日本時間の朝6時に `src/index.js` の `scheduled()` が動く |
| ブラウザの機能 | Canvas、WebGL、Web Audio、カメラ・マイク、音声認識・音声合成、傾きセンサー、ホーム画面に追加（PWA）など | そのまま使える |
| AI（DeepSeek） | 会話、判定、採点、文章やデータの生成 | `src/ai.js` の `askAI()` を使う |
| ライブラリ | ゲーム、3D、物理、音、認識など | `docs/ライブラリ.md` の条件で選ぶ |
| 無料の外部API・公開データ | 百科事典、地図、天気、図鑑のデータなど | `docs/ライブラリ.md` の条件で選ぶ |

- `src/room.js` の `Room` クラスは、名前と export を消さない（中身は自由に変えてよい）。部屋を増やすときは、`Room` の中で部屋の名前ごとに分けて使う
- `scheduled()` の中身は自由に書いてよい

### 設定を足すとき

上の表にない設定（Durable Objectsのクラスを増やす、Cronの時刻を変える、など）は、`wrangler.jsonc` の変更が必要になる。このファイルは先生が反映する。

1. 作品のコードは、その設定を使う形で作ってよい
2. `wrangler.jsonc` に足す設定を、変更案として作者に見せる
3. 作者に「この変更案を先生に相談して」と伝える

## 使わないもの

費用・安全のために、次のものは使わない。

- Workers AI（使った分だけ費用がかかる）
- 有料のサービス、支払いが必要なサービス、有料の外部API
- 登録やAPIキーが必要な外部サービス（使いたいときは、作者に「先生に相談して」と伝える）
- 外部のログインサービス、外部のデータベース

## AIを使う

AIは、サーバー（`src/index.js`）から `src/ai.js` の `askAI()` を呼んで使う。ブラウザから直接は呼ばない。

```js
import { askAI, AIError } from "./ai.js";

try {
  const answer = await askAI(env, [
    { role: "system", content: "（AIの役割や性格）" },
    { role: "user", content: "（利用者が入力した文）" }
  ]);
  // answer には、AIの返事の文字列が入る
} catch (e) {
  if (e instanceof AIError && e.code === "limit") {
    // 今日の回数を使い切った。画面に「今日はここまで」などを出す
  }
}
```

- `e.code` は `"limit"`（今日の回数を使い切った）、`"bad_request"`（messages の形がちがう）、`"unavailable"`（AIにつながらない。少し待つ）、`"unauthorized"`（合言葉の問題。先生に相談）のどれか
- 返事は文字列。`askAI(env, messages, { json: true })` として、指示の中でも「JSONで返して」と書けば、ステージ・問題・キャラクターの設定などのデータも作れる。受け取ったら `JSON.parse` して、形が正しいかを確かめてから使う
- 画像・音声・音楽は作れない。画面に絵や声が必要なときは、素材、コードで描く絵、ブラウザの音声合成などと組み合わせる
- 1日に呼べる回数には上限がある（今は1日200回。先生が変えることがある）。**作品を使う全員の合計**なので、節約する作りにする（ボタンを押したときだけ呼ぶ、同じ質問の答えはデータベースに保存して使い回す、など）。毎フレームや自動で何度も呼ぶ作りにはしない
- 1回の返事の長さにも上限がある。長い文章やたくさんのデータが必要なときは、何回かに分けて頼む
- AIへの入力は、中国にあるDeepSeekのサーバーで処理される。利用者が入力する画面には「個人情報を書かないでね」という注意書きを出す

## 保存と提出のしかた

作者に「提出して」と言われたら、次の順で行う。

1. 変更したファイルの一覧を作者に見せる
2. `git add` と `git commit` をする（メッセージは日本語で短く）
3. `git push origin dev` で、`dev` ブランチに送る
4. 送れたかどうかを、作者に報告する

- 送る前の確認は、手元（`npx wrangler dev`、`http://localhost:8787`）で行う。スマホや友達の端末での確認は、公開したあとのURLで行う
- 本番の公開は、先生が内容を確認して `main` に反映したときに行われる。本番のURLは `https://（作者の名前）.kaizuacademy.com`
- `main` には絶対に送らない

## 環境の問題は、先生に任せる

このPCの環境（Node.js・Git・送信用の鍵・`wrangler.jsonc`・`.dev.vars`・AIの中継）は、先生が用意している。次のようなときは、自分で直そうとせず、エラーの文をそのまま作者に見せて「先生に相談して」と伝える。

- `git push` が認証のエラーで失敗する
- `npm install` や `npx wrangler dev` が、作品のコードと関係のないエラーで失敗する
- `askAI()` が、回数の上限以外のエラーを返す

このとき、次のことはしない。

- 鍵・トークン・パスワードを作者に聞く、入力させる、ファイルやURLに書く
- `git config` の認証の設定や、Windowsの資格情報を変える
- 先生が用意したファイルを書き換えて、エラーを消そうとする
