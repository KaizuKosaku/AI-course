# このプロジェクトでAIが守ること

このファイルには、作品を作るための「技術の前提」と「安全のルール」だけを書いています。
**何を作るか、どう作るかは、作者（このPCを使っている生徒）が決めます。** 作者の指示と、作者が docs/ に書いた文書に従ってください。

## この前提の考え方

- ここに書いた決まりは、**安全と費用を守るためのもの**。作者の理想を小さくする理由にしない
- 作者のやりたいことが、この環境でそのままできないときは、できる方法を探す。それでも難しいときは、近い体験を実現する別の方法を提案する。「できません」だけで終わらせない
- 説明は、作者にわかるやさしい言葉で（専門用語には一言の説明をつける）。ただし、作るものの質は落とさない

## 最初に読むファイル

- `docs/環境と公開.md` … 開発の環境、使える技術、手元での動かし方、提出の方法
- `docs/安全チェック.md` … 公開する前に確かめること
- `docs/ライブラリ.md` … ライブラリ・外部API・素材の選び方

## 技術の前提

- 作品は **Cloudflare Workers で公開するWebアプリ** として作る。公開URLは `https://（作者の名前）.kaizuacademy.com` で、世界中の人が見る
- 画面はブラウザで動く形で作る（ライブラリやフレームワークを使ってよい）
- 費用がかかるものは使わない。使えないものは `docs/環境と公開.md` の「使わないもの」に書いてある。それ以外は、`docs/ライブラリ.md` の条件を満たせば使ってよい
- ファイルやフォルダーは、必要に応じて増やしてよい
- 次のファイルは先生が用意したもの。**変更しない**。変更が必要になったら、変更案を作者に見せて「先生に相談して」と伝える
  - `wrangler.jsonc`（Cloudflareの設定）
  - `src/ai.js`（AIを呼ぶための関数）
  - `.dev.vars`（手元で使う合言葉）
  - `.gitignore`
- `src/room.js` の `Room` クラスは、名前と export を消さない（中身は自由に変えてよい）
- データベースの表を作る・変えるときは、`migrations/` に新しいSQLファイルを追加する。すでにあるSQLファイルは書き換えない

## 安全のルール（必ず守る）

- APIキー・合言葉・パスワードなどの秘密の値を、コードやドキュメントに書かない
- 利用者が入力した文字を画面に表示するときは `innerHTML` を使わず、`textContent` などを使う
- DeepSeekのAIを使うときは、必ず `src/ai.js` の関数を通す。AIのサービスに直接つながない。ブラウザから直接AIを呼ばない
- 書き込み・投稿・AIの呼び出しには、回数の上限をつける
- 本名・顔写真・学校名・住所などの個人情報を、作品やドキュメントに入れない。外部のサービスにも送らない
- 他の人が作った画像・音楽・キャラクター・作品名を、許可なく使わない

## 保存と提出（git）のルール

- 作者に「セーブして」と言われたら、`git add` と `git commit` をする。コミットメッセージは日本語で、何をしたかを短く書く
- 作者に「提出して」と言われたら、`docs/環境と公開.md` の「提出のしかた」に従う
- 送る（push）ときは、**必ず `dev` ブランチに送る**。`main` ブランチには絶対に送らない
- 強制的な上書き（force push）、履歴の書き換え、ブランチの削除はしない
- 作者に「さっきのセーブに戻して」と言われたら、戻す前に、どのセーブに戻るのかを作者に見せて確認する
