## 1. この回のねらい

DAY05では、Manusに開発を任せ、その間に別の仕事を進めた。今日は同じ「任せる」を、**自分のPCのコーディングエディタの中**で行います。ファイル・設計書・APIという、開発のしくみがそのまま見える場所でAIと作るのが新しい点です。

前半のニュースは、後半の開発とつながるように並べています。

| ニュースで見ること | 後半の開発でやること |
|---|---|
| AIは目標を、どんな手を使ってでも達成しようとする（テスト環境の事件） | 目標と「やってはいけないこと」を、設計書に先に書く |
| 作る人たちが安全のしくみを求めている（公開書簡） | 変更は人間が確かめてから承認する |
| AIは役割ごとに得意な形に分かれていく（Jev） | エディタのAIと、チャットAIを使い分ける |

冒頭でこう言い切ってください。**「今日のニュースに出てくる問題は、今日君がエージェントを使うときにも、小さな形で起きる」**

## 6. 想定トラブルと対処

| 起きること | 対処 |
|---|---|
| Zedが起動しない（白い画面） | GPUドライバー更新、またはDirectX 11非対応。2人1組にする |
| DeepSeekがエラー401 | キーの貼りつけミス。前後の空白・改行を確認 |
| DeepSeekがエラー402 | 残高不足。管理画面でチャージ |
| DeepSeekがエラー429 | 混雑。少し待って再送 |
| ゲームが真っ白 | F12 → Consoleの赤いエラーを全文、プロンプト③で渡す |
| 外部ライブラリを使われた | 「docs/仕様書.md のお約束を読み直して、外部のものを使わずに作り直して」 |
| ドライブに提出できない | Googleへのログインを確認。だめなら先生がまとめて受け取る |
| エージェントが時間内に終わらない | 先生の見本ゲームで「設計書と見比べて確かめる」作業をさせる |
